# reactive-state-runtime-go

一套零外部服务依赖的响应式状态与副作用调度运行时。把**状态（State）**、
**派生计算（Derived）** 与 **副作用（Effect）** 登记成一张依赖图，
一次状态变更后，运行时会以可预测的方式完成传播、求值与异步副作用调度。

```go
rt := reactive.New(reactive.Options{MaxConcurrency: 4, MaxQueue: 64})
defer rt.Close()

a := rt.State("a", 1)
b := rt.Derive("b", func(s *reactive.Scope) (any, error) {
    return s.Must(a).(int) * 2, nil          // 动态登记依赖 a
})
rt.Effect("log", []reactive.Handle{b}, func(c *reactive.EffectContext) error {
    v, _ := c.Get(b)
    return c.Set(someState, v)               // 过期/取消时写回会被丢弃
})

rt.Update(func(tx *reactive.Tx) error {      // 事务：全部生效或全部不生效
    tx.Set(a, 10)
    return nil
})
rt.Flush()                                   // 等待已触发的副作用完成
```

## 调度语义

### 事务提交（`Update` / `Set`）

- 一次 `Update` 中的全部修改**原子生效**：`fn` 返回错误或 panic 时，
  所有修改被丢弃，状态不会停留在中间态。
- `fn` 在运行时锁内执行（可串行化），应只使用 `tx.Get` / `tx.Set`，
  不要调用 `Runtime` 的其它方法（会死锁）。`tx.Get` 读到的是本事务视角的值，
  因此读-改-写（如计数器自增）在并发提交下不会丢失更新。
- 读取方（`Runtime.Get`、派生计算、副作用）只能看到某个**已提交的完整版本**，
  不会观察到提交进行中的中间状态。

### 派生计算传播

- 一次提交后，受影响的派生节点按拓扑序（Kahn 算法，同层按节点创建顺序）
  **各求值一次**，且总是基于该批变更的最新值：菱形依赖不会导致重复求值，
  也不会暴露中间态。
- 派生计算的依赖是**动态**的：每次求值时通过 `Scope.Get` / `Scope.Must`
  实际读到的节点集合即为新的依赖集，未再读取的旧依赖自动摘除。
- 求值顺序、求值次数与最终状态只取决于初始状态与操作序列，
  不依赖 map 遍历顺序、系统时间或随机量。

### 副作用调度

- 副作用在其依赖于一次提交中发生变化时被触发，**异步**执行；
  登记时会触发一次初始执行。同一批触发按节点创建顺序 FIFO 提交。
- **单在途**：同一副作用同一时刻只允许一个在途执行。在途期间的新触发会
  取消当前执行（`EffectContext.Done` 关闭）并记录一次待重跑，
  当前执行退出后以最新值重跑一次（多次触发会合并）。
- **过期丢弃**：每次执行有单调递增的代次（`Gen`）。被取代、被取消、
  超时（`EffectOptions.Timeout`）或节点被注销后，该次执行的
  `EffectContext.Set` 写回一律失败（`ErrDisposed`），错误回调也不会触发。
- 副作用之间互不影响：慢副作用只占用自己的 worker，
  不会阻塞无关分支（并发度 > 1 时）。

## 一致性保证

- **原子提交**：事务要么全部生效要么完全不生效。
- **无中间态**：派生计算在一次提交中只求值一次，读到的是同批最新值。
- **无过期写回**：较早发起但较晚返回的副作用结果必然被丢弃。
- **可串行化并发**：并发提交在单锁下串行化，最终状态与某个串行顺序一致，
  且不丢失更新。
- **异常隔离**：派生计算返回错误或 panic 会被捕获为该节点的错误态，
  沿依赖链传播给读取它的节点（`Scope.Get` 返回该错误），无关分支不受污染；
  失败的节点保留最近一次成功值，后续变更可使其恢复一致。
- **资源有界**：`Dispose` 注销节点后，运行时不再持有其引用、不再调度它；
  副作用队列有界，长期运行不无界增长。

## 配置（`Options`）

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `MaxConcurrency` | 4 | 副作用最大并发执行数 |
| `MaxQueue` | 64 | 等待执行的副作用队列深度上限 |
| `Overflow` | `Reject` | 队列满策略：`Reject` 拒绝本次触发；`DropOldest` 丢弃队首任务 |
| `OnOverflow` | nil | 触发被拒绝时的回调（可观测） |
| `OnEffectError` | nil | 副作用（未被取代的）执行返回错误时的回调 |

`EffectOptions`：`Timeout`（单次执行超时，超时即取消并丢弃结果）、
`OnError`（该副作用的错误回调）。

## 动态增删

- `Runtime.Dispose(h)` 注销状态/派生/副作用节点：移除其全部依赖边，
  取消在途副作用；仍引用它的派生订阅者会被触发重算，
  从而通过动态依赖机制摘除它（读到 `ErrDisposed`）。
- 正在传播的更新不受图结构变化影响：传播在锁内同步完成，
  `Dispose` 与提交互斥，不会丢失或错配。

## 测试

```sh
go test -race ./...
```

覆盖：批量提交（成功/失败/panic）、菱形依赖与求值次数、求值顺序确定性、
并发提交、异常传播与恢复、panic 捕获、动态依赖切换、节点注销、
异步乱序丢弃、单在途、取消与超时、队列溢出（Reject / DropOldest）、
慢副作用隔离、动态增删副作用、无界增长检查。
